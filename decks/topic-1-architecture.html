The brief, in one breath.

  • Index pokemondb.net, Pokémon detail pages only (1,025 of them).
  • Build a search UI in Atomic or Headless. Type and Generation facets. Image-rich result cards.
  • Ship it: GitHub, public URL.
  • Optional: RGA, Query Suggest, detail page, Passage Retrieval.

I shipped Essential + Intermediate + Advanced + Bonus.

Two sources, one regex.

Sources

  • pokedex-sandbox — start URL /pokedex/bulbasaur, no link following. Lets me iterate on the scraping config in 10 seconds.
  • pokedex-full — start URL /pokedex/national, follows links matching the inclusion regex.

Inclusion / Exclusion

# inclusion (regex)
^https://pokemondb\.net/pokedex/[a-z0-9-]+$

# exclusions (wildcard)
/move/*
/type/*
/ability/*
/item/*
/evolution/*
/stats/*
/sprites/*
/forms/*
/location/*
/pokedex/national
/pokedex/stats/*

Result: 1,025 documents, no junk.

Indexing · 3 of 3
07

Generation, derived not extracted.

pokemondb.net does not surface Generation N as a single DOM node. National No. is a stable cell. Generation ranges are canonical:

RangeGen
1 – 151I
152 – 251II
252 – 386III
387 – 493IV
494 – 649V
650 – 721VI
722 – 809VII
810 – 905VIII
906 – 1025IX
 
# Indexing Pipeline Extension
import re

GEN_RANGES = [
  (1,151,1),(152,251,2),(252,386,3),
  (387,493,4),(494,649,5),(650,721,6),
  (722,809,7),(810,905,8),(906,1025,9),
]

natdex = document.get_meta_data_value(
    "pokemon_natdex"
) or []
m = re.search(r"\d+", str(natdex[0])) if natdex else None

if m:
  n = int(m.group(0))
  for low, high, gen in GEN_RANGES:
    if low <= n <= high:
      document.add_meta_data(
        {"pokemongeneration": str(gen)}
      )
      break

Pure data layer. Re-run the IPE without re-crawling when a new generation drops.

UI · 2 of 3
09

Result template — image first.

function ResultTemplate(result: Result) {
  const raw = result.raw as Record<string, unknown>;
  const image      = raw.pokemonimage as string  | undefined;
  const generation = raw.pokemongeneration as number | undefined;
  const species    = raw.pokemonspecies as string | undefined;
  const natdex     = raw.pokemonnatdex as string | undefined;

  return (
    <article className="poke-card">
      {image && <img src={image} alt={result.title} />}
      <div className="poke-card__body">
        <h3><AtomicResultLink /> <span>№ {natdex}</span></h3>
        <AtomicResultMultiValueText field="pokemontypes" />
        {generation != null && <GenerationBadge generation={generation} />}
        {species && <span>{species}</span>}
      </div>
    </article>
  );
}

Atomic primitives where they help (AtomicResultLink, AtomicResultMultiValueText). Plain HTML where they don't.

UI · 3 of 3
10

The API key never reaches the browser.

The pattern

  • API key sits in Vercel env vars.
  • /api/token exchanges it for a search token scoped to PokedexSearch.
  • Headless engine's renewAccessToken re-mints on 401.
  • Browser only ever holds short-lived tokens.
// api/token.ts (Vercel Function)
const url = `https://${orgId}.org.coveo.com
              /rest/search/v2/token`;
const upstream = await fetch(url, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${API_KEY}`,
  },
  body: JSON.stringify({
    searchHub: 'PokedexSearch',
    userIds: [{
      name: 'pokedex-anonymous',
      provider: 'Email Security Provider',
      type: 'User',
    }],
  }),
});

This is the FDE-correct deployment pattern — and the right opener for a customer security review.

ML · 1 of 3
11

Relevance Generative Answering, in three clicks.

  • Models → Add → Relevance Generative Answering.
  • Filter to @source==pokedex-full. The model only sees Pokémon pages.
  • Associate with the Pokedex query pipeline.
  • Front-end is already wired: <AtomicGeneratedAnswer /> lights up the moment the model is active.

Why this matters at a real customer: RGA is the natural answer for "how do I…" questions. The hard part is never the component — it's which content the model is allowed to ground on. The filter is the FDE control surface.

ML · 2 of 3
12

Query Suggestions, with the cold-start problem named.

  • QS models train on Coveo Usage Analytics. ~10,000 queries for "great", but you can ship sooner.
  • Sandbox path: Test configuration mode ON; seed UA by replaying ~30 curated queries against /rest/search/v2.
  • Production path: connect search hubs early, accept that the first 30 days the suggestions are mediocre — then accept ART (Auto-Relevance Tuning) joining QS on the same pipeline as the value compounds.

Naming the cold-start tradeoff in the deck — instead of pretending it's fully populated — is the FDE move.

13

Pipeline statements as the relevance-tuning surface.

# Boost legendary canon
$qre(expression: '@pokemonname=="mewtwo" OR @pokemonname=="rayquaza" OR …',
     modifier: '300')

# Synonyms (reduce keyword fragility)
@thesaurus("legendary" => "mewtwo, mew, lugia, ho-oh, rayquaza, dialga, …")
@thesaurus("starter"   => "bulbasaur, charmander, squirtle, …")

# Featured query — when the user types "pikachu" by name
@featured(condition: 'when query is "pikachu"',
          expression: '@pokemonname=="pikachu"', boost: '1000')

Pipeline statements + ML models are the two surfaces a Technical Success team has to teach customers. They're complementary, not competing — statements are explicit business policy; models are observed behavior.

Bonus · 1 of 2
14

Ask the Pokédex.

Why faceting alone is no longer enough.

Question: "Which Gen 1 Pokémon has the highest Special Attack?"

The Type facet can't answer this. Even RGA on the result set is awkward — you'd have to sort, then narrow, then read.

The Passage Retrieval API answers it directly by ranking passages, not documents. The base-stats table from each Gen 1 entry gets weighted independently, and Mewtwo's row floats.

POST /rest/search/v3/passages/retrieve
Authorization: Bearer <token>

{
  "query": "Which Gen 1 Pokémon has
            the highest Special Attack?",
  "searchHub": "PokedexQA",
  "filter": "@source==\"pokedex-full\"",
  "maxPassages": 5,
  "additionalFields": [
    "pokemonname", "pokemonimage",
    "clickableuri"
  ],
  "localization": { "locale": "en-US" }
}
Bonus · 2 of 2
15

Passage Retrieval is the substrate.

"Passage Retrieval is to agentic AI what the search index was to web search — the part the customer never sees, but the part everything else stands on."
  • Today: powers Coveo for Agentforce, the Atlas knowledge layer, and any "ground my LLM in our content" use case.
  • Tomorrow: every agentic feature the customer wants to build — copilots, action recommenders, deflection bots — calls this endpoint, not /search/v2.
  • FDE leverage: showing customers this endpoint is how we move them from "Coveo is our search" to "Coveo is our retrieval substrate."

Lessons
19

What I'd do with another week.

  • Push, not Crawler, for half of it. The static parts of pokémondb (base stats, types) are perfect for the crawler. But for "live" data — Pokémon GO availability, smogon competitive tiers — Push gives me real-time, no recrawl. Showing both connectors side-by-side would be a stronger teaching artifact.
  • Streamed RGA citations. The current RGA component is great as a black box. Streaming the citation events into a custom React component would let me demo "watch the model decide what to ground on," which is the conversation customers actually want.
  • Properly seeded UA. I'd run a synthetic-user script for a week to give Query Suggest real data, then graph the model's Active → trained → relevant transition. Better demo, better honesty about ML cold-start.
